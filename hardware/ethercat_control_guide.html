Part I

The shape of the protocol.

What the drive does, what it expects from the master, and the seven CiA 402 states that gate every motion.

§ 01 — Supported operating modes

Seven modes, two used in this repo.

The MyActuator V4 EtherCAT firmware advertises seven CiA 402 operating modes. The pendulum stack currently uses only two — CST for the ONNX deploy path and PVT for the impedance-control bring-up — but a future humanoid bring-up will likely add CSP and Homing as well, so they're documented here too.

Mode valueAbbrev.NameWhat master sendsWhere the loop closes
1PPProfile PositionTarget position + profile params; Bit4 triggerDrive (trapezoidal planner + position loop)
3PVProfile VelocityTarget velocity + ramp params; Bit4 triggerDrive (velocity ramp + speed loop)
5PVTPVT / MIT impedancepos, vel, τ_ff, K_p, K_d every cycleDrive (MIT law each cycle)
6HomingHomingMode change onlyDrive (current position → zero)
8CSPCyclic Sync PositionTarget position every cycleDrive (position loop)
9CSVCyclic Sync VelocityTarget velocity every cycleDrive (velocity loop)
10CSTCyclic Sync TorqueTarget torque every cycleMaster (drive runs current loop only)

CST (Mode 10) is the deploy path for the ONNX policy — the master computes torque every 20 ms and the drive's current loop tracks it. PVT (Mode 5) is the impedance path mirroring Isaac Lab's ImplicitActuatorCfg — the drive runs the PD law at 1 kHz with K_p / K_d streamed from the master.

The cyclic modes (CSP / CSV / CST / PVT) expect data every bus cycle. The profile modes (PP / PV) are one-shot — write the target, raise Bit 4 (New Setpoint) on the control word, and the drive plans the rest. Homing is even simpler: switch to Mode 6, enable, and the current position becomes the zero point.

§ 02 — EtherCAT communication architecture

Master, slaves, one frame per cycle.

The X6 drive is a slave on the bus. The master sends one Ethernet frame per cycle; each slave reads its own segment from the passing frame, writes back its feedback into the same frame, and the frame returns to the master. Bandwidth utilisation can exceed 90 % — the protocol is built for tight cyclic control.

Two data classes share the bus:

ClassPurposeTimingUsed for
PDOProcess Data Object — cyclic data exchangeEvery cycle (e.g. 1 kHz)Control word, target / actual position, target / actual torque, status word
SDOService Data Object — request / responseAcyclic, non-real-timePID gains, limits, mode of operation (when not in PDO)

PDO mapping is configured in PreOP state. Once the bus is brought up to OP, the mapping is fixed for that session — changing it later requires dropping back to PreOP. This is why icub_x6_drive.yaml and icub_x6_drive_mit.yaml declare their RxPDO 0x1600 / 0x1601 in the slave-config YAML rather than at runtime.

Why PDO over SDO. SDO writes are request / response and take multiple cycles. For a 1 kHz control loop you want target torque to land in the same cycle you wrote it — that requires PDO. The PDF's headline 90 % bandwidth figure assumes most of the traffic is PDO.
§ 03 — CiA 402 state machine

Seven states, one required enable sequence.

Before the drive will accept torque or position commands it must be walked through the CiA 402 state machine to Operation Enabled. The master controls the walk via the Control Word (0x6040); the drive reports its current state via the Status Word (0x6041). There is no shortcut — sending a non-zero torque while the drive is in Switch On Disabled just gets ignored.

The seven states

StateWhat it means
Initialization 初始化Drive boots and self-tests. Parameters cannot be set, motion cannot start.
Switch On Disabled 伺服无故障Self-test passed. Parameters can be configured.
Ready To Switch On 伺服准备好Ready for power-on. Parameters still writable.
Switched On 等待打开伺服使能Power applied to motor, waiting for enable. Holding position but no commanded motion.
Operation Enabled 伺服运行Commands take effect. The motor will rotate when target ≠ 0 and mode is set.
Quick Stop Active 快速停机Quick Stop deceleration in progress per 0x605A option code.
Fault Reaction Active / Fault 故障Drive detected a fault. All commands inhibited until reset.

Standard enable procedure

To enter Operation Enabled in any cyclic mode, walk this seven-step sequence:

  • Set the operating mode Write 0x6060 = 1/3/5/6/8/9/10 depending on the target mode (e.g. 8 for CSP).
  • Write Control Word = 0x0006 (Shutdown) Master sends 0x6040 = 0x0006.
  • Wait for Ready To Switch On (0x0231) Poll 0x6041 until lower bits = 0x231.
  • Write Control Word = 0x0007 (Switch On) 0x6040 = 0x0007.
  • Wait for Switched On (0x0233) 0x6041 lower bits = 0x233.
  • Write Control Word = 0x000F (Enable Operation) 0x6040 = 0x000F.
  • Wait for Operation Enabled (0x0237) 0x6041 lower bits = 0x237. The motor is now live; in CST/CSP/CSV/PVT modes every PDO write takes effect.
Fault state requires a Fault Reset before re-enabling. If the drive enters Fault, the enable sequence above will not work. First send Fault Reset — a rising edge on Control Word bit 7 (i.e. write 0x0080). The drive performs a system reset, transitions to Switch On Disabled, and only then can the enable sequence be repeated. A constant 0x0080 does nothing — it must be a rising edge.
Part II

The object dictionary.

Every entry the X6 exposes — what it does, what unit it takes, and where in your YAML it shows up.

§ 04 — Object dictionary classification

Three address bands, three provenances.

CiA 402 partitions the address space by who defines the entry. Communication objects live in 0x1000–0x1FFF, vendor-specific objects in 0x2000–0x2FFF, and the CiA 402 profile (control word, modes, targets, actuals) in 0x6000–0x6FFF. Knowing which band you're in tells you whether you can copy code between vendors.

Address rangeCategoryExamples
0x1000–0x1FFFCommunication / EtherCATPDO mapping (0x1600–0x1603, 0x1A00–0x1A03), SM-PDO assignment (0x1C12, 0x1C13)
0x2000–0x2FFFVendor-specificPVT_KP (0x2000), PVT_KD (0x2001), inner-loop PID gains (0x2002–0x2008), motor / drive temperature, bus voltage
0x6000–0x6FFFCiA 402 drive profileControl Word (0x6040), Status Word (0x6041), Modes of Operation (0x6060), targets & actuals

Code that drives a CiA 402 motor over EtherCAT — Synapticon, Kollmorgen, Inovance — uses the 0x6xxx band identically. The vendor-specific 0x2xxx band is where vendors differ; the MyActuator PVT_KP object would be at a completely different index on another drive. Cross-vendor code reuse stops at 0x2000.

§ 06 — Control Word, Status Word, Modes

The three objects every cycle touches.

Control Word — 0x6040

AttributeValue
TypeUINT16
AccessRW, RxPDO mappable
Default0x0000

Beyond the bits in § 03, the Control Word also drives the parameter-save protocol.

  • Write ControlWord = 0 (init first stage).
  • Write ControlWord = 4096 (0x1000) — triggers save.
  • Within 3 s, write ControlWord = 0 — confirms save; the drive commits modified parameters to flash.
  • Saving is rejected if the drive is in Operation Enabled. Always disable first.

Status Word — 0x6041

AttributeValue
TypeUINT16
AccessRO, TxPDO mappable
Default0x0000

Bits 0–9 encode the CiA 402 state (see § 03). Bit 10 = Target Reached; bit 13 = Following Error; bit 12 is repurposed per active mode (PP mode "Set Point Acknowledge", CST/CSV mode flags).

Modes of Operation — 0x6060 (write) / 0x6061 (read)

0x6060 sets the mode. 0x6061 echoes the active mode — and returns 0 if the drive has a fault. A 0 readback on 0x6061 while you're commanding torque is a strong signal that you're in Fault and the drive is silently dropping your commands.

§ 07 — Targets, actuals, error code

What you send vs what you read.

Target Position — 0x607A · INT32 · pulses

  • PP mode: write target, then trigger Bit 4 rising edge on Control Word to start trajectory planning.
  • CSP mode: value written every cycle is used directly as position reference (plus 0x60B0 Position Offset).
  • PVT mode: used as desired position p_des in the MIT control law.

Target Velocity — 0x60FF · INT32 · pulses/s

  • CSV mode: drive tracks target velocity each cycle, no trajectory planning.
  • PV mode: Bit 4 rising edge triggers ramp.
  • PVT mode: desired velocity v_des in the MIT control law.

Target Torque — 0x6071 · INT16 · ‰ of rated current

  • CST mode: direct torque command, no speed / position protection. Always pair with 0x6072 Max Torque as a safety clamp.
  • PVT mode: torque feedforward t_ff (added on top of K_p·err + K_d·dot_err).
unit conversion — target torque → motor current $$ I_{actual} \;=\; \text{TargetTorque} \times 0.001 \times I_{rated} $$

TargetTorque = 500 corresponds to 50 % of rated current. This is per-mille of rated current, not rated torque — see the X6 reality note in tuning/motor_id_protocol.html § 12 for why the master-side YAML factor has to be calibrated against the measured K_t · I_rated product.

Actual Position / Velocity / Torque — 0x6064 / 0x606C / 0x6077

Read-only feedback. 0x6064 is encoder pulses; 0x606C is encoder pulses per second; 0x6077 is per-mille of rated current, computed as:

torque-actual formula $$ \text{TorqueActual} \;=\; \frac{\text{IqFilter} \times 1000}{\text{MOTOR\_RATE\_IQCURRENT}} $$

§ 08 — Profile parameter objects

Velocity, acceleration, deceleration — for the profile modes.

PP and PV modes need profile parameters so the drive's trajectory planner has something to work with. CSP / CSV / CST do not use these — there is no on-drive planner in cyclic modes.

Profile Velocity — 0x6081 · UINT32 · encoder pulses/s

Maximum operating speed in PP mode. The drive auto-converts the written pulses-per-second to its internal RPM units:

internal speed conversion $$ \text{POSPLAN\_MAXSPD (RPM)} \;=\; \frac{\text{ProfileVelocity}}{\text{Resolution}} \times \text{GearRatio} \times 60 $$

Profile Acceleration / Deceleration — 0x6083 / 0x6084 · UINT32 · pulses/s²

Acceleration and deceleration limits used in PP and PV. Internal conversion:

internal accel conversion $$ \text{POSPLAN\_ACC (deg/s}^2\text{)} \;=\; \frac{\text{ProfileAcceleration} \times 360}{\text{Resolution}} \times \text{GearRatio} $$

Quick Stop Deceleration — 0x6085 · UINT32 · pulses/s²

Used during Quick Stop when 0x605A (Quick Stop Option Code) = 0: the drive decelerates at this rate to zero speed and then transitions to Switch On Disabled.

§ 09 — Position monitoring parameters

Software limits, following error, target window.

Software Position Limit — 0x607D · RECORD

Sub-index 1 = min INT32; sub-index 2 = max INT32. Target position in PP mode is clamped to this range before the planner runs. Has no effect in CSP / CSV / CST — in cyclic modes you must enforce limits master-side.

Following Error Window — 0x6065 · UINT32 (pulses)

Default 131072 (one encoder revolution). If |position_demand − position_actual| exceeds this for longer than 0x6066, the drive sets Status Word bit 13 and faults.

Following Error Timeout — 0x6066 · UINT16 (ms)

Default 10 ms.

Position Window / Position Window Time — 0x6067 / 0x6068

0x6067 default 100 pulses; 0x6068 default 10 ms. After the actual position stays inside the window for longer than the time, Status Word bit 10 (Target Reached) is set. Setting 0x6067 = 0 disables the target-reached detection; setting 0x6068 = 0 makes it immediate.

Following Error Actual — 0x60F4 · INT32 (RO)

Live following error in pulses. Mappable in TxPDO 0x1A03 for tracking-error analysis.

Position, velocity, torque feedforward.

These three objects let the master inject feedforward terms into the drive's control loops. In high-precision applications they typically come in via RxPDO 0x1603, alongside the standard control channel.

§ 11 — Max torque and rated current

The two SDOs that define the torque envelope.

Max Torque — 0x6072 · UINT16 · ‰ of rated current

Sets the output limit of the speed loop — equivalently, the maximum torque the drive will command:

$$ \text{OutMax} \;=\; \text{MaxTorque} \times 0.001 \times I_{rated} $$
The calculated current cannot exceed motor stall current. If MaxTorque ×0.001 × I_rated > MOTOR_STALL_IQCURRENT, the drive silently clamps to stall. Setting MaxTorque = 0 also reverts to the stall-current limit — so a missing write does not mean "no limit", it means "stall ceiling".

For the X6 in the pendulum rig (I_rated = 13.40 A, K_t = 2.0095 N·m/A), 0x6072 = 2500 corresponds to 25 % rated current ≈ 6.7 A ≈ 13.46 N·m at the shaft — half of motor rated. icub_x6_drive.yaml sets it there as a deliberate safety cap.

Motor Rated Current — 0x6075 · INT32 · mA

Reference value for all per-mille torque conversions. Default = MOTOR_RATE_IQCURRENT × 1000. Writes update the internal rated-current parameter; the drive refuses values exceeding stall current. This is the single number that, when changed, breaks every YAML factor that converts ‰ to amps to torque — handle with care.

§ 12 — Homing method

One method: set current position as zero.

The X6 supports a single homing method: switching to Mode 6 sets the current motor position as the zero point. No limit switch, no index pulse — just write 0x6098 (any non-zero), switch 0x6060 to 6, enable, and PosZero updates internally.

IndexTypeBehaviour
0x6098INT8Homing Method — Mode 6 of 0x6060 sets current position = zero.

After homing, switch 0x6060 back to whatever cyclic mode you actually want to run (CST / CSP / PVT). The homing zero point persists until power cycle or another homing pass.

§ 13 — Vendor-specific objects

The 0x2000 band — and where the ×1000 trap lives.

Everything in 0x2000–0x2FFF is MyActuator-specific. Two of these objects, PVT_KP and PVT_KD, are the heart of the impedance-control path — and both expect the master to write a value 1000× the actual gain you want.

PVT_KP — 0x2000 · INT32

PVT proportional gain scaling $$ K_{p,\text{actual}} \;=\; \text{PVT\_KP}_{\text{written}} \times 0.001 $$

PVT_KD — 0x2001 · INT32

PVT derivative gain scaling $$ K_{d,\text{actual}} \;=\; \text{PVT\_KD}_{\text{written}} \times 0.001 $$
Want an effective stiffness of 2 Nm/rad? Write 0x2000 = 2000. Want damping 0.1 Nm·s/rad? Write 0x2001 = 100. Skip the ×1000 and the drive sees gains 1000× weaker than you intended; multiply twice and you'll get a violent oscillation.
This scaling was undocumented in the previous protocol revision. The repo's earlier icub_x6_drive_pvt.yaml wrote raw int32 with factor: 1.0, which forced empirical gain discovery on every bring-up. The icub_x6_drive_mit.yaml introduced in May 2026 bakes the 1000× into the slave YAML's factor field — so when pvt_publisher.py publishes kp = 2.0 as an engineering value, the wire carries the int32 2000 and the drive applies an actual gain of 2.

§ 14 — PDO mapping principles

What goes on the wire each cycle.

PDOs are bundles of object-dictionary entries packed into a single EtherCAT frame segment. RxPDO carries master-to-slave data — control word, targets, gains. TxPDO carries slave-to-master data — status word, actuals, telemetry. The drive supports up to four mappings of each direction; the master picks which to activate via the SM-PDO assignment registers (§ 17).

§ 17 — SM-PDO assignment (0x1C12 / 0x1C13)

Switching mappings in PreOP.

PDO assignments can only be changed while the bus is in PreOP. Once OP is reached the active mapping is locked until the next state transition. Switching from default 0x1600 to PVT-capable 0x1601 takes three SDO writes.

IndexAttributeNotes
0x1C12RxPDO AssignmentDefault 1 active channel = 0x1600. Available = 0x1600, 0x1601, 0x1602, 0x1603. Modify in PreOP only.
0x1C13TxPDO AssignmentDefault 1 active channel = 0x1A00. Available = 0x1A00, 0x1A01, 0x1A02, 0x1A03.

Switching to PVT — three SDO writes in PreOP

  • Clear the assignment SDO write 0x1C12 sub 0 = 0 — sets the active-channel count to zero.
  • Assign channel 1 to 0x1601 SDO write 0x1C12 sub 1 = 0x1601.
  • Activate one channel SDO write 0x1C12 sub 0 = 1 — sets the active count back to 1, now pointing at 0x1601.

For multi-channel setups (e.g. RxPDO 0x1600 + RxPDO 0x1603 for CSP with feedforward) the pattern extends: sub 0 = 0; sub 1 = 0x1600; sub 2 = 0x1603; sub 0 = 2.

Part IV

The seven operating modes.

Each mode's required PDOs, operation sequence, and the master/drive responsibility split.

§ 18 — CSP · Cyclic Sync Position · Mode 8

Master interpolates, drive tracks.

In CSP, the master sends a target position every cycle. The drive performs no trajectory planning — it just closes the position loop on whatever number the master hands it. Trajectory smoothness is the master's problem.

Required PDOs

  • RxPDO: Control Word (0x6040), Target Position (0x607A), Modes of Operation (0x6060) — i.e. mapping 0x1600.
  • TxPDO: Status Word (0x6041), Position Actual (0x6064) — i.e. mapping 0x1A00.
  • Optional: Position Offset (0x60B0), Velocity Offset (0x60B1), Torque Offset (0x60B2) — i.e. add mapping 0x1603.

Operation steps

  • In PreOP — configure PDO mapping (default 0x1600 + 0x1A00 is sufficient).
  • Write Modes of Operation = 8.
  • Execute CiA 402 enable sequence: 0x0006 → 0x0007 → 0x000F.
  • Each cycle — write Target Position (0x607A).
  • Read Position Actual (0x6064) to confirm tracking.
CSP supports velocity feedforward (0x60B1) and torque feedforward (0x60B2) — both significantly improve trajectory tracking. Activate RxPDO 0x1603 alongside 0x1600 for high-precision applications.
§ 19 — CSV · Cyclic Sync Velocity · Mode 9

Direct velocity command, drive follows.

In CSV mode the master sends a target velocity every cycle and the drive's speed loop tracks it directly — no trajectory planning. Required PDOs: Control Word + Target Velocity (0x60FF) + Modes of Operation in RxPDO; Status Word + Velocity Actual (0x606C) in TxPDO.

Operation steps

  • Configure PDO mapping.
  • Write Modes of Operation = 9.
  • Execute CiA 402 enable sequence.
  • Each cycle — write Target Velocity (0x60FF). Unit: encoder pulses/s.
  • Read Velocity Actual (0x606C) to confirm tracking.
§ 20 — CST · Cyclic Sync Torque · Mode 10

Direct torque, no speed or position protection.

CST hands the master direct control of the current loop's setpoint. Every other safety the drive normally provides — speed limit, position limit, trajectory planning — is bypassed. This is also the mode the ONNX policy uses in this repo.

Operation steps

  • Configure PDO mapping.
  • Write Modes of Operation = 10.
  • Execute CiA 402 enable sequence.
  • Each cycle — write Target Torque (0x6071). Unit: ‰ of rated current.
  • Read Torque Actual (0x6077) to confirm tracking.
CST mode controls motor torque directly without speed/position protection. Always set Max Torque (0x6072) first to clamp current draw. In config/ethercat/icub_x6_drive.yaml this is configured as 0x6072 = 2500 (≈ 13.46 N·m shaft torque, half motor rated) — a deliberate safety cap on an otherwise unbounded command. Raise toward 743 (the value matching effort_limit = 20 Nm at the rated K_t · I_rated product) only after empirical validation.
§ 21 — PP · Profile Position · Mode 1

Set a point-to-point target, drive plans.

PP mode is one-shot: the master writes a target position plus profile parameters (velocity, acceleration, deceleration), then triggers motion by raising a control-word bit. The drive runs a trapezoidal trajectory planner internally and reports back when it reaches the target window.

Related objects

  • Target Position — 0x607A
  • Profile Velocity — 0x6081
  • Profile Acceleration — 0x6083
  • Profile Deceleration — 0x6084
  • Position Limit — 0x607D (clamps target before planner runs)
  • Position Window / Time — 0x6067, 0x6068 (Target Reached judgment)
  • Following Error — 0x6065, 0x6066, 0x60F4

Operation steps

  • Configure PDO mapping (recommended: 0x1600 + 0x1602 for profile params on the wire).
  • Write Modes of Operation = 1.
  • Set motion parameters via SDO or PDO: 0x6081, 0x6083, 0x6084, 0x607D.
  • Execute state-machine enable sequence.
  • Write Target Position (0x607A).
  • Set Control Word Bit 4 rising edge to trigger motion — write 0x000F first, then 0x001F.
  • Monitor Status Word Bit 10 (Target Reached) to detect completion.

PP mode uses the rising edge of Control Word Bit 4 (New Setpoint) to start each new motion. Sequence: write target → flip Bit 4 from 0 → 1 → drive plans & moves → Status Word Bit 10 = 1 when target reached → clear Bit 4 (0x000F) → repeat for next motion. A constant Bit 4 = 1 does not queue continuous motions — only the rising edge fires.

§ 22 — PV · Profile Velocity · Mode 3

Ramped velocity, drive plans the slope.

In PV mode the master writes a target velocity plus acceleration/deceleration parameters; the drive runs an internal velocity ramp. Like PP, motion is triggered by a Bit 4 rising edge on the control word.

Operation steps

  • Configure PDO mapping.
  • Write Modes of Operation = 3.
  • Set Profile Acceleration (0x6083) and Profile Deceleration (0x6084).
  • Execute state-machine enable sequence.
  • Write Target Velocity (0x60FF).
  • Trigger Bit 4 rising edge to start the ramp.
  • Monitor Status Word Bit 10 — set when target velocity is reached within ±50 pulses tolerance.
§ 23 — PVT / MIT · Mode 5

The impedance mode.

PVT (also called MIT mode) is a hybrid control mode where the master streams desired position, velocity, torque feedforward, and PD gains every cycle; the drive computes output torque internally per the MIT impedance law. It's the mode that matches Isaac Lab's ImplicitActuatorCfg behaviour, which is why this repo uses it for the impedance-control bring-up.

drive-side control law (Mode 5) $$ \tau \;=\; K_p \cdot (p_{des} - p_{fb}) \;+\; K_d \cdot (v_{des} - v_{fb}) \;+\; t_{ff} $$
p_des
Desired position from 0x607A, converted to radians at the drive.
p_fb
Actual position feedback.
v_des
Desired velocity from 0x60FF, converted to rad/s.
v_fb
Actual velocity feedback.
K_p
Position gain. Drive reads 0x2000 PVT_KP and applies × 0.001 internally.
K_d
Velocity gain. Drive reads 0x2001 PVT_KD and applies × 0.001 internally.
t_ff
Torque feedforward from 0x6071 Target Torque, in ‰ of rated current.

Required PDO

Must use RxPDO 0x1601 because PVT_KP and PVT_KD are not in the standard mapping. Switch with the three-write PreOP sequence in § 17.

Operation steps

  • In PreOP — switch RxPDO to 0x1601. SDO writes: 0x1C12 sub 0 = 0 · 0x1C12 sub 1 = 0x1601 · 0x1C12 sub 0 = 1.
  • Write Modes of Operation = 5.
  • Execute CiA 402 enable sequence.
  • Each cycle — write the five-channel command vector: 0x607A Target Position (pulses) · 0x60FF Target Velocity (pulses/s) · 0x6071 Target Torque (‰ of rated) as feedforward · 0x2000 PVT_KP = K_p × 1000 · 0x2001 PVT_KD = K_d × 1000.
PVT mode is well-suited to joint impedance control. Adjusting K_p and K_d gives different stiffness / damping profiles without leaving the cyclic loop. Combined with K_p = K_d = 0 the drive becomes a pure torque feedforward port — equivalent to CST.

From a clean enable, with the drive limp:

  • Step 1 — enter Mode 5 with K_p = K_d = 0, ff_torque = 0, target = current actual position. Confirm there is no torque kick on transition.
  • Step 2 — ramp K_d (damping) first: write 0 → 100 → 500 (actual 0.1 → 0.5 Nm·s/rad). Push the link by hand; it should resist motion without holding position. Listen for chatter.
  • Step 3 — ramp K_p (stiffness): write 0 → 500 → 2000 (actual 0.5 → 2.0 Nm/rad) with the target held at the current position. Link should resist gentle pushes and return to the hold point.
  • Step 4 — command a small step (≤ 10°) and verify the response shape. Expand range only after the step looks clean.
  • Hard stop at any growling, overcurrent (0x603F bit set), or following-error timeout (0x6065 / 0x6066 trip).

The cyclic SDO/PDO sequence above is the drive-side half of PVT bring-up. The ros2_control integration lives in pendulum_pvt_control: one controller plugin (PendulumPVTController) claims the position / velocity / effort / kp / kd command interfaces, packs them into RxPDO 0x1601 every cycle, and exposes a streaming ~/setpoint + a FollowJointTrajectory action server on top.

The drive_side_pd parameter is the seam: true (default) for real hardware — the law in Eq. above runs in drive firmware; false for Gazebo — the controller runs the same law in software and claims only the effort interface. The RxPDO 0x1601 channel order and byte count must match the firmware ESI exactly; the layout used here lives in config/ethercat/icube_x6_drive_pvt.yaml, with the × 1000 scaling for PVT_KP / PVT_KD baked into the channel factor so gains are commanded in engineering units (N·m/rad, N·m·s/rad). See the PVT tuning field note's caveat section for the full list of gotchas.

§ 24 — Homing · Mode 6

Set current position as zero.

Homing mode does one thing: sets the current motor position as the new zero point. After execution, PosZero is updated internally and persists until the next homing pass or power cycle.

Operation steps

  • Write Modes of Operation = 6.
  • Execute state-machine enable sequence.
  • The drive automatically sets the current position as zero.
  • After homing — switch to your target operating mode (CST, CSP, PVT, etc.).
§ 25 — Quick Stop

The controlled stop path.

From Operation Enabled, sending Control Word = 0x0002 triggers the Quick Stop sequence. Behaviour depends on 0x605A Quick Stop Option Code.

0x605A valueBehaviour
0Decelerate via 0x6085 Quick Stop Deceleration to zero speed, then transition to Switch On Disabled.

For an emergency situation that needs to be cleared and re-enabled, Quick Stop is the right path. For an uncontrolled hard stop (e.g. E-stop circuit), drop EtherCAT power — the drive will fault on watchdog, and you'll need the Fault Reset sequence (§ 03) to bring it back.

Part V

Four worked examples.

The pseudocode the PDF ships, reproduced here so you can copy-paste from a single source. Plus fault recovery.

§ 26 — Example: CSP mode motor control

Master interpolates, drive tracks.

// 1. In PreOP, configure PDO mapping
//    Default 0x1600 + 0x1A00 is fine for basic CSP.

// 2. Bus transition: PreOP → SafeOP → OP

// 3. Set operating mode
SDO_Write(0x6060, 0x00, 8);          // Mode = CSP

// 4. CiA 402 enable sequence
PDO_Write(0x6040, 0x0006);           // Shutdown
Wait_StatusWord(0x0021);             // Ready To Switch On
PDO_Write(0x6040, 0x0007);           // Switch On
Wait_StatusWord(0x0023);             // Switched On
PDO_Write(0x6040, 0x000F);           // Enable Operation
Wait_StatusWord(0x0027);             // Operation Enabled

// 5. Stream target position every cycle
while (running) {
    position = TrajectoryGenerator();    // master-side planner
    PDO_Write(0x607A, position);         // Target Position
    PDO_Write(0x60B1, vel_ff);           // Velocity Offset (optional)

    actual_pos = PDO_Read(0x6064);       // Position Actual
    status     = PDO_Read(0x6041);       // Status Word
}
§ 27 — Example: PP point-to-point motion

Trigger via Bit 4 rising edge.

// 1. Set operating mode
SDO_Write(0x6060, 0x00, 1);          // Mode = PP

// 2. Configure motion parameters
SDO_Write(0x6081, 0x00, 10000);      // Profile Velocity (pulses/s)
SDO_Write(0x6083, 0x00, 50000);      // Profile Acceleration
SDO_Write(0x6084, 0x00, 50000);      // Profile Deceleration

// 3. Enable
PDO_Write(0x6040, 0x0006);
PDO_Write(0x6040, 0x0007);
PDO_Write(0x6040, 0x000F);

// 4. Write target and trigger motion (Bit4 rising edge)
PDO_Write(0x607A, 131072);           // Target: 1 rev at 17-bit encoder
PDO_Write(0x6040, 0x001F);           // Enable + New Setpoint

// 5. Wait for arrival
while (!(PDO_Read(0x6041) & 0x0400)) {
    // Wait for Target Reached (bit 10)
}

// 6. Prepare next motion — clear Bit 4
PDO_Write(0x6040, 0x000F);

// 7. New target, re-trigger
PDO_Write(0x607A, 0);                // Target: back to zero
PDO_Write(0x6040, 0x001F);           // Trigger new setpoint
§ 28 — Example: PVT / MIT impedance control

Five channels every cycle, with the ×1000 scaling visible.

// 1. In PreOP, switch RxPDO to 0x1601
SDO_Write(0x1C12, 0x00, 0);          // Clear
SDO_Write(0x1C12, 0x01, 0x1601);     // Use Mapping 1
SDO_Write(0x1C12, 0x00, 1);          // Activate

// 2. Set operating mode
SDO_Write(0x6060, 0x00, 5);          // Mode = PVT

// 3. Enable
PDO_Write(0x6040, 0x0006);
PDO_Write(0x6040, 0x0007);
PDO_Write(0x6040, 0x000F);

// 4. Cyclic PVT command vector
while (running) {
    PDO_Write(0x607A, target_pos);   // Position (encoder pulses)
    PDO_Write(0x60FF, target_vel);   // Velocity (pulses/s)
    PDO_Write(0x6071, torque_ff);    // Torque FF (‰ rated current)
    PDO_Write(0x2000, kp * 1000);    // PVT_KP — write 1000× the actual gain
    PDO_Write(0x2001, kd * 1000);    // PVT_KD — write 1000× the actual gain
}

The icub_x6_drive_mit.yaml slave configuration in this repo already bakes the 1000× into the EtherCAT YAML factor field, so the master-side publisher can publish K_p and K_d in engineering units and let the slave-yaml multiplication handle the on-wire scaling.

§ 29 — Example: SDO PID tuning + parameter save

Live-tune the three-loop cascade.

// Read current PID parameters
cur_kp = SDO_Read_Float(0x2002, 0x00);  // CUR_LOOP_KP
cur_ki = SDO_Read_Float(0x2003, 0x00);  // CUR_LOOP_KI
spd_kp = SDO_Read_Float(0x2004, 0x00);  // SPD_LOOP_KP
spd_ki = SDO_Read_Float(0x2005, 0x00);  // SPD_LOOP_KI
pos_kp = SDO_Read_Float(0x2006, 0x00);  // POS_LOOP_KP
pos_ki = SDO_Read_Float(0x2007, 0x00);  // POS_LOOP_KI
pos_kd = SDO_Read_Float(0x2008, 0x00);  // POS_LOOP_KD

// Modify speed-loop gains
SDO_Write_Float(0x2004, 0x00, 2.5);     // SPD_KP = 2.5
SDO_Write_Float(0x2005, 0x00, 0.01);    // SPD_KI = 0.01

// Save to flash — motor must be disabled first
SDO_Write(0x6040, 0x00, 0);             // ControlWord = 0
SDO_Write(0x6040, 0x00, 4096);          // ControlWord = 0x1000 (trigger save)
SDO_Write(0x6040, 0x00, 0);             // ControlWord = 0 (confirm — within 3 s)
The save sequence is rejected in Operation Enabled. Disable the motor before writing 0 → 4096 → 0, otherwise the values modify the live PID loops but are not persisted. After power cycle they revert to the stored values.
§ 30 — Fault detection & recovery

How the drive reports, how to clear.

Detection

  • Error Code (0x603F) — read the specific fault. See § 07 for the value table.
  • Modes of Operation Display (0x6061) — returns 0 whenever a fault is active, even if 0x6060 says otherwise. A 0 echo while you're commanding non-zero mode is the strongest signal you're in Fault and the drive is dropping commands silently.

Recovery sequence

  • Check Error Code (0x603F) to confirm the cause.
  • Eliminate the fault cause — clear overvoltage / overcurrent / over-temperature condition, fix mechanical jam, etc.
  • Send Fault Reset: set Control Word Bit 7 — write 0x0080. This must be a rising edge, not a sustained value.
  • Drive performs system reset and transitions to Switch On Disabled.
  • Walk the standard enable sequence again — 0x0006 → 0x0007 → 0x000F.
Fault Reset is a rising edge, not a level. A code path that holds 0x0080 high will reset once and then do nothing on subsequent faults. Flip Bit 7 low between resets.

§ 01 — Principles

What this system is, and what it is not.

This is a design language for dense, technical writing — engineering field notes, research summaries, tuning guides, RFC-adjacent documentation. It prioritizes legibility, information density, and reference-ability over decoration. The aesthetic borrows from restored technical textbooks, oscilloscope interfaces, and scientific instrument panels.

01
Warmth over sterility

A near-black warm background reads for hours without fatigue. Pure black + pure white is a hostile surface for reading math.

02
One accent, used decisively

Amber is the only saturated color used at scale. Cyan, rose, moss are for semantic roles (data, warnings, success) and appear rarely.

03
Metadata is part of the design

Labels, section numbers, units, eyebrow text, footnotes — they aren't clutter. Visible structure is the entire point.

04
Three fonts, distinct roles

Fraunces for editorial voice. IBM Plex Sans for body prose. JetBrains Mono for code, numbers, labels. Never mix roles.

05
Density with air

Long sections, tight line-height in panels, generous breathing room between sections. Dense blocks separated by space.

06
Decoration earns its place

The grain overlay, dashed rules, and labels punching through borders all carry meaning or soften a flat digital surface. Nothing is decoration for its own sake.

§ 02 — Color system

Three backgrounds, three inks, one accent.

The palette has nine colors. That sounds like a lot; in practice, six of them are structural (three background depths, three ink strengths) and you rarely touch them directly — they're referenced by CSS variables. The remaining three do semantic work.

§ 03 — Typography

Three fonts, three jobs, no overlap.

The fonts are chosen for contrast between roles. Fraunces is editorial and humanist — it signals "this is writing." Plex Sans is neutral, highly legible at small sizes, and has excellent weight range. JetBrains Mono handles code, numbers, and anywhere precision matters. Each font does one job.

Fraunces · display + pull quotes
The closed loop is a second-order system.

Used for: H1, H2, H3, subtitles, callouts. Italic weight 300 for headlines; roman 400–500 for subheads. Optical size axis handles large display sizes beautifully. Never use Fraunces for body text or labels.

IBM Plex Sans · body text
Clean, neutral, highly legible. Renders math descriptions and prose equally well. Set at weight 300 for body, 500 for emphasis.

Used for: all running prose, variable descriptions, card copy. Weights: 300 body, 500 strong, 600 rare emphasis. Line-height 1.65 for paragraphs, 1.5 for compact blocks.

JetBrains Mono · code, numbers, labels
τ = Kp·(θd − θ) + Kd·(θ̇d − θ̇)

Used for: code blocks, inline code, metadata labels (all-caps tracked), numeric readouts, section numbers, eyebrow text, table contents. Letter-spacing 0.15–0.3em on all caps; 0 on code.

§ 04 — Layout & spacing

One column, generous margins, deliberate rhythm.

The layout is intentionally conservative. A single 1180px content column contains everything. Internal two- and three-column grids appear inside specific sections but never dictate the main flow. Reading should be sequential and uninterrupted.

Content widths

  • Wrap: max-width: 1180px, 32px side padding on desktop, more on large displays only if needed.
  • Prose paragraph: max-width: 70ch. Do not stretch body text across the full 1180. Measure matters.
  • Lead paragraph: max-width: 68ch, slightly larger font, brighter ink.
  • Callout: max-width: 60ch. Shorter lines match the italic voice.
  • Steps list: max-width: 72ch. Slightly wider because the number prefix eats horizontal room.

§ 05 — Structural patterns

How a page announces itself.

Three recurring patterns carry most of the structural weight: the eyebrow, the section number, and the labeled panel. Together they make every block self-identifying — the reader always knows what they're looking at.

Pattern 1 — Eyebrow text

PD Control · Feedforward · Motor ID

A title appears here.

Short, all-caps, monospace, tracked to 0.3em, amber. Sits above the page title and any major section to contextualize what follows. Think of it as the "department" of the article.

Pattern 2 — Section numbers (§)

§ 04 — Step response, interactively

What ζ and ωn actually look like.

Uses the section sign (§) plus zero-padded number plus em-dash plus short descriptor. Same mono + amber + tracked style as the eyebrow. Makes sections navigable and referenceable ("see §09").

Pattern 3 — Labeled panels

Panels have a label that sits on their top border, like a callout on a schematic. The label is set on data-label and rendered via ::before. The background of the label matches the page so it appears to punch through the border.

This pattern is the visual signature of the system. Use it for anything you want to foreground: important callouts, math definitions, warnings (with .warn variant), code blocks (via data-lang).

<!-- CSS implementation -->
.panel {
  background: var(--bg-panel);
  border: 1px solid var(--rule);
  position: relative;
}
.panel::before {
  content: attr(data-label);
  position: absolute;
  top: -9px;       /* pulls label up onto the border */
  left: 20px;
  background: var(--bg); /* matches page to break border */
  padding: 0 10px;
  font-family: var(--mono);
  font-size: 10px;
  letter-spacing: .25em;
  color: var(--amber);
  text-transform: uppercase;
}
§ 06 — Components

The building blocks.

Panel — .panel[data-label]

The default panel. Slightly lifted background, thin border, labeled through data-label. Use for grouping related content, call-to-attention blocks, rules-of-thumb lists.

Callout — .callout

Callouts are editorial. Fraunces italic, 2px amber left border, no background. Use for a single memorable sentence that summarizes a section or offers a mental model.

Warning — .warn

Warning. Used for failure modes, common mistakes, things that will silently break. Rose-tinted gradient background, 2px rose left border. The word at the start is bolded and also rose.

Steps list — ul.steps

  • Zero the encoder Each step has a strong header (first line) followed by descriptive prose. The number comes from a counter, zero-padded, in mono amber. Dashed bottom border between items.
  • Measure the baseline Second step. Note that numbering is automatic via counter-reset and counter-increment.

Bullets — ul.bullets

  • Custom arrow bullet (→) in amber, via ::before. Use instead of disc bullets.
  • Short-ish items. If items are multi-line and structural, prefer ul.steps.
  • Max-width 68ch keeps measure tight.
§ 07 — Content blocks

Math, code, tables.

Math blocks — .math-block

Math is rendered with KaTeX (loaded via CDN). Wrap display math in .math-block.labeled with a caption:

Eq. 1 — canonical second-order form $$ \ddot\theta + 2\zeta\omega_n\,\dot\theta + \omega_n^2\,\theta = \omega_n^2\,\theta_d $$

For inline equation fragments without KaTeX, use .inline-eq for a mono-amber treatment: ω_n, K_p = Jω_n². Follow every math block with either a variable legend (dl.vars) or prose that uses the symbols introduced.

Variable legend — dl.vars

θ
joint angle (rad)
ωn
natural frequency, how fast the loop responds (rad/s)
ζ
damping ratio — how much it rings

Code blocks — pre[data-lang]

Code blocks have an amber-deep left border (makes them instantly identifiable at skim), a mono-tracked language label in the top-right via data-lang, and a custom tokenization:

# comments → --ink-faint italic
def tune_gains(J: float, wn: float, zeta: float = 0.7):
    """strings → --moss"""
    Kp = J * wn**2           # numbers → --amber
    Kd = 2 * zeta * (Kp*J)**0.5
    return Kp, Kd           # keywords → --rose

Tokenization is applied manually with span classes (.tok-k, .tok-s, .tok-c, .tok-n, .tok-f). For longer documents, swap in a library like highlight.js and map its classes to these colors.

Reference tables — table.ref

ParameterValueNote
First columnMono amberLast column gets .v class — Plex Sans, --ink-dim, more prose-like.
Second columnMono defaultWorks for any rows where you want the value column neutral.

Tables are mono throughout except for td.v cells, which soften to Plex Sans for readable prose. Headers are amber on amber-deep underline. Row dividers are solid --rule.

§ 08 — Data visualization

Charts as part of the page, not pasted on.

Charts use Chart.js with a small set of overrides that make them feel native to the page. Key moves: background matches panels, grid lines fade into the background, primary series uses amber, secondary series uses cyan, warning series uses rose.

Chart.js defaults

Chart.defaults.font.family = "'JetBrains Mono', monospace";
Chart.defaults.font.size = 11;
Chart.defaults.color = '#a79a82';      // --ink-dim
Chart.defaults.borderColor = '#2a2419'; // --rule

const COLORS = {
  amber: '#e8a33d',    // primary series
  cyan:  '#5fb3b3',    // secondary / measured
  rose:  '#d97757',    // warning / wrong-way
  moss:  '#8fa968',    // success
  dim:   '#6b6354',    // reference lines
  grid:  '#1e1a13',    // --rule-soft
};

const gridOpts = {
  grid: { color: COLORS.grid, drawBorder: false },
  ticks: { color: '#6b6354', font: { size: 10 } },
};

Chart wrappers

Wrap every chart in .graph-wrap. It provides the panel background, a title-bar, a description line, and a fixed canvas height (340px desktop / 280px mobile). Controls (sliders) go in .controls underneath; computed readouts go in .readouts below that.

  • One dominant color per chart. Amber for the thing you're highlighting. Reference lines get --ink-faint with a 4,4 dash.
  • Grid is almost invisible. --rule-soft on grid lines, no chart border.
  • Axis labels in mono. Tiny, tracked, --ink-faint. Always include units in brackets: time [s], torque [N·m].
  • Tooltips match the page. Background --bg-inset, title amber, body ink. Matches the rest of the design.
§ 09 — Micro-details

What makes it feel made.

Grain overlay

A fixed, pointer-events-none, SVG noise overlay at ~3.5% opacity sits on top of everything. Kills the flat-digital feel. Identical technique to film grain in video editing. Keep opacity below 5% or it reads as damaged rather than textured.

Dashed vs solid rules

  • Solid rules (--rule): section dividers, panel borders, table bottom borders. They announce structure.
  • Dashed rules (--rule-soft): soft breaks within a section, list dividers, TOC separators. They suggest relationship without demanding attention.

Labels that punch through borders

The single most recognizable motif: labels on panels, math blocks, and the hero header sit on top of their border, with background: var(--bg) matching the page so they appear to break the line. Costs 5 lines of CSS, transforms the feel.

Zero-padded numbers

Section numbers, list items, meta labels all use counter(x, decimal-leading-zero) for zero-padded display: 01, 02, 03 instead of 1, 2, 3. Monospace alignment, archival feel.

Clamp() for responsive type

Headlines use font-size: clamp(min, preferred, max) so they scale fluidly with viewport width. The big H1 clamps 44px → 7vw → 88px. No media queries needed.

Background gradients

Two radial gradients on the body — one top-right, one upper-left — add warmth without committing to a visible color. Extremely subtle (#1a1409 fading to transparent over 1200px). Gives a sense of an actual room with light sources, not a flat digital plane.

Font weights are structural

Plex Sans body is weight 300, not 400. This is deliberate — the thinner body makes weight 500 emphasis feel like a real shift. On a light background 300 would be too faint; on warm dark it reads perfectly.

§ 10 — What to avoid

How this aesthetic fails.

  • Too much amber. Every designer's first instinct is to paint everything in the accent color. One amber element per screenful of content is often enough. When everything is emphasized, nothing is.
  • Extra colors. Adding a fifth or sixth hue dilutes the palette. If you need a new semantic role, ask whether an existing color fits before inventing.
  • Pure black text on dark. --ink is #ece2cf, warm off-white. Never use pure white — it vibrates against the warm background.
  • Swapping Fraunces for another serif. Fraunces' personality comes from its optical-size axis and italic quirks. Replacing it with something generic (Playfair, Lora) deletes the editorial voice.
  • Centering body text. The layout is left-aligned throughout. Centering breaks the rhythm and hurts scannability.
  • Icons. This system doesn't use icons except within charts. Icons would compete with the typographic emphasis system. If you need a visual break, use a panel or divider.
  • Shadows and depth effects. No drop shadows, no glassmorphism, no glow. The layered feel comes from background-lightness differences only.
  • Animated transitions. Buttons and links have tiny transitions (color change on hover). Beyond that, nothing animates. No scroll-linked effects, no fade-ins.
§ 11 — Starter template

The skeleton, ready to paste.

Copy this into a new .html file. It imports the fonts, KaTeX, and Chart.js, and includes the CSS token block plus all component styles. Fill in the content.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>Your document</title>

  <!-- KaTeX for math -->
  <link rel="stylesheet"
        href="https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/katex.min.css">
  <script defer src="https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/katex.min.js"></script>
  <script defer src="https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/contrib/auto-render.min.js"
     onload="renderMathInElement(document.body,{
       delimiters:[{left:'$$',right:'$$',display:true},
                   {left:'$',right:'$',display:false}],
       throwOnError:false});"></script>

  <!-- Chart.js -->
  <script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.0/dist/chart.umd.min.js"></script>

  <!-- Fonts -->
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

        family=Fraunces:ital,opsz,wght@0,9..144,300;0,9..144,400;0,9..144,600;1,9..144,400

  <style>
    /* ...paste the CSS token block + component styles here... */
